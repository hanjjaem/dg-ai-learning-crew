기획 01 · 문제 정의 (Why?)

"카카오톡 단톡방 인증은 왜 총무를 지치게 만드는가?"

🎯 기획자의 문제 의식: "단톡방에 회원들이 대화 링크를 올릴 때마다 대화가 계속 쌓여 끝없이 스크롤해야 하고, 총무는 매일 밤 '누가 냈는지, 누가 미제출인지, 벌금(2,000원)은 얼마인지' 엑셀을 켜놓고 수기로 대조해야 한다."

대부분의 프로젝트는 "무엇을 만들까?"부터 생각하다가 산으로 갑니다.
기획자는 "총무가 매일 밤 겪는 가장 끔찍한 반복 업무가 무엇인가?"를 먼저 정의해야 합니다.
우리의 목표는 단톡방을 돕는 보조 툴이 아니라, 카카오톡 인증 자체를 없애고 총무의 관리 업무를 '0초'로 만드는 것이었습니다.

💡 기획 포인트: 기술이 중요한 게 아닙니다. 현업의 '진짜 고통'을 정확히 짚어내는 것이 기획의 90%입니다.
기획 02 · 사용자 경험(UX) 3대 원칙 수립

"'3초 컷' 공식 Share 링크 기반 무마찰 인증"

📐 기획자가 수립한 3대 불변의 원칙: 1. "3초 컷" 공식 Share 링크 (Zero Friction): 복잡한 절차 없이, ChatGPT/Claude의 공유 URL 복붙 ➡️ AI 도구 자동 감지 ➡️ 1초 인증 완료
2. PC 데스크톱 업무 최우선 (Desktop-First): 듀얼 모니터 업무 환경에 최적화된 1200px~1920px 와이드 대시보드
3. 지식 자산화 (Knowledge Hub): 동료가 검증한 실무 프롬프트 원클릭 복사

인증하는 데 10초 이상 걸리거나 복잡하면 크루원들은 참여를 포기합니다.
크루원들이 매일 실제로 하는 액션은 '대화방의 Share(공유) 버튼을 눌러 링크를 복사하는 것'뿐입니다.
이 실제 행동에 정확히 맞춰 [Ctrl+V 링크 붙여넣기] ➡️ [1초 완료] 흐름을 기획의 절대 원칙으로 못 박았습니다.

💡 기획 포인트: 사용자의 실제 업무 습관(Share 링크 복사)에 완벽하게 일치하는 '무마찰(Zero Friction)' 환경을 설계하세요.
기획 03 · AI를 통제하는 헌법 (AGENTS.md)

"AI가 헛소리 못 하게 규칙 문서를 먼저 쥐어줘라"

📜 AGENTS.md 프로젝트 통제 지침: • 비전 통제: 카톡 단톡방 완전 대체 및 독립형 지식 플랫폼 지향
• UI 통제: 과도한 섀도우 배제, 1200px 와이드 데스크톱 우선
• 품질 통제: 코드 수정 후 반드시 `npm run build` 자체 무결성 검증

AI에게 매번 채팅으로 길게 설명하면 맥락을 까먹고 엉뚱한 코드를 짜기 시작합니다.
프로젝트 최상단에 `AGENTS.md`라는 헌법 파일을 박아두면, AI는 모든 코딩과 의사결정 시 이 지침을 최우선으로 복종하게 됩니다.

💡 기획 포인트: AI에게 일을 시키기 전, '프로젝트 규칙 문서'를 먼저 작성하는 사람이 일류 기획자입니다.
구현 01 · 과감한 쳐내기 (Focus & Cut)

"드롭다운 기능은 왜 있어야 될까? 단일화해."

🗣️ 실제 지시 프롬프트: "드롭다운 기능은 왜 있어야 될까? 단일화해. 헤더를 꾸미지 말고 구조적으로 분리해라. 1px 라인만 쓰고 그림자는 빼."

개발자가 편하자고 넣어둔 15명 전환 스위처와 과도한 입체 그림자를 기획자가 단칼에 잘라냈습니다.
군더더기 기능을 뺄수록 동료들이 매일 켜두어도 눈이 피로하지 않은 단정한 SaaS 대시보드가 완성됩니다.

💡 실습 포인트: "이 기능 진짜 쓰는 거야?"라고 끊임없이 의심하고 과감히 삭제하세요.
확장 02 · 사내 기존 자산(코드) 재활용

"공모전 폴더 참고해서 이미지 어떻게 올렸는지 확인해봐"

🗣️ 실제 지시 프롬프트: "프롬프트뿐만 아니라 생성한 그림, HTML도 전시했으면 좋겠는데 가능해? D:\work\동구_공모전\app 이 폴더 참고해서 이미지 어떻게 올렸는지 확인해볼래?"

새 기능을 만들 때 AI에게 막연히 "이미지 업로드 만들어줘" 하면 엉뚱한 기술을 들고 옵니다.
구청 안에 이미 검증된 공모전 프로젝트 경로를 레퍼런스로 딱 지정해주자, 클라우드 스토리지 연동과 모달 UI를 단 10초 만에 완벽히 복제해냈습니다.

💡 실습 포인트: 맨땅에 헤딩하지 말고, 사내에 이미 존재하는 레퍼런스 폴더를 AI에게 가리키세요.
디버깅 03 · 말보다 빠른 캡처 1장 투척

"이게 뭐야? 모달이 내부에 파묻혀 있잖아. 재진단해!"

🗣️ 실제 지시 프롬프트: "이게 뭐야 상세 모달로 열려야 하는거 아니야? (화면 캡처 첨부) 아니 모달이 내부에 파묻혀있잖아. 재점검 해봐 재진단!"

모달 상단이 화면 밖으로 잘려나가는 복잡한 CSS 버그가 터졌습니다.
기획자는 어려운 기술 용어를 쓸 필요가 없습니다. 화면 캡처 한 장을 던지며 "파묻혔잖아!"라고 지적하자, AI가 부모 요소 갇힘 버그를 파악하고 React Portal로 화면 전체를 장악하게 치료했습니다.

💡 실습 포인트: 에러 설명하려 애쓰지 마세요. 스크린샷 1장이 천 마디 말보다 빠릅니다.
UX 고도화 04 · 사용자 주도권 확립

"버튼 말고 행을 눌러도 튕기는데 이게 맞아? 버튼을 눌러야지."

🗣️ 실제 지시 프롬프트: "아카이브에서 마우스 클릭하면 외부 링크로 연결되는 부분이 뭐뭐있어? 버튼 말고 행 전체를 눌러도 이동하는데 이게 맞아? 특정 버튼을 눌러야 이동시켜야지."

텍스트를 보려고 행을 눌렀는데 예고 없이 외부 사이트로 튕겨나가는 나쁜 UX를 기획자가 잡아냈습니다.
"행 클릭 = 내부 상세 모달 열기" vs "`[ ↗ ]` 버튼 클릭 = 외부 사이트 새 탭 열기"로 명확히 분리하여 사용자에게 완벽한 통제권을 주었습니다.

💡 실습 포인트: 사용자가 의도하지 않은 강제 화면 이동을 원천 차단하세요.
DB 설계 05 · ERD 모델링 & 총무 4대 방어 스키마

"실제 데이터 넣기 전에 DB 설계부터 해야지. ERD 설계해봐."

🗣️ 실제 지시 프롬프트: "좋아 이제 샘플 데이터는 지우고 실제 데이터로 테스트해 보자. 그전에 DB 설계부터 해야겠지? ERD 설계해봐. 관리자 입장에서 부족한 부분 없어? 스키마 구성해줘 그리고 Supabase에 구축해."

임시 화면 목업에서 진짜 영구 보존 시스템으로 넘어가는 가장 중요한 관문입니다.
기획자가 "관리자 입장에서 부족한 게 뭐지?"라고 되묻자, 단순 회원/제출 테이블을 넘어 실제 공무원 운영에서 반드시 필요한 4대 특화 테이블이 구축되었습니다:

1. 출장·연차 면제 테이블 (`crew_exemptions`): 출장 시 벌금 2,000원 자동 면제
2. 회비 1원 단위 장부 원장 (`crew_fee_ledger`): 입금, 환급, 시상금 투명 복식부기
3. 법정공휴일 자동 제외 (`crew_holidays`): 추석·대체공휴일 벌금 미부과
4. 개인정보 블라인드 (`is_hidden`): 대외비·민원정보 원클릭 숨김

💡 실습 포인트: 비개발자도 "ERD 설계해봐", "관리자 입장에서 빠진 게 뭐야?" 한마디면 엔터프라이즈급 SQL 스키마가 도출됩니다.
실전 런칭 06 · 초기 회비 8만원 & 실데이터 자산화

"초기 회비 8만원으로 수정하고, 8명 입금완료 처리해."

🗣️ 실제 지시 프롬프트: "초기 회비 8만원으로 수정해. 김남희, 남수현 등 8명 입금완료 처리. 이현아 복지정책과로 수정. 지금까지 작업한 내역 깃허브에 올려줘."

가짜 테스트 데이터를 싹 비우고, 실제 16명 크루원 명단과 8명 완납(640,000원, 50%) 실데이터를 Supabase DB와 스토리지에 동기화했습니다.
마지막으로 GitHub 원격 저장소에 프로젝트 전체를 안전하게 백업·푸시하여 동구청의 공공 디지털 자산으로 런칭을 완료했습니다.

💡 실습 포인트: 기획과 DB가 완성되면 실제 데이터로 즉시 라이브 테스트를 진행하고 깃허브에 영구 보존하세요.
