# 입력과 콘텐츠 규격

## 사용자 입력

필수는 교육주제 한 줄이다. 선택 입력은 대상, 숙련도, 시간, 결과물, 실습 기기, 사용 도구, 참고자료, 디자인, 기획만/전체 제작이다. 예:

```text
workflows/education-web-deck/SKILL.md를 읽고 실행해줘.
교육주제: AI에게 Git 작업을 맡기고 다른 PC에서 개발 이어가기
대상: 비개발자 공무원 / 시간: 75분 / 도구: ChatGPT와 Codex
실습: 명령어를 직접 치지 않고 에이전트에게 시키기
스타일: 큰 키워드와 일상 비유가 있는 강연형
```

주제만 입력해도 된다. 생략한 값은 자동으로 확정하지 않고 인터뷰에서 한 항목씩 정한다. 사용자가 `추천해줘` 또는 `나머지는 추천해서 초안`이라고 한 항목만 가정으로 채운다.

## 인터뷰 설계판

인터뷰가 진행되는 동안 대화에 다음 상태를 짧게 유지한다.

| 항목 | 상태 |
|---|---|
| 주제 | 사용자 입력 |
| 대상과 교육 이유 | 확정 / 미정 / 추천안 |
| 교육 후 행동·결과물 | 확정 / 미정 / 추천안 |
| 시간과 현장 환경 | 확정 / 미정 / 추천안 |
| 실제 어려움·사례 | 확정 / 미정 / 추천안 |
| 강연·실습 비율과 분위기 | 확정 / 미정 / 추천안 |

한 답변 뒤에는 새로 확정된 내용과 그것이 시나리오에 주는 영향을 보여준다. 모든 질문 목록을 한꺼번에 보내지 않는다. 필수 항목이 모이면 설계판을 한 번 요약하고 사용자 확인을 받은 뒤 `brief.md`와 1차 `scenario.md`를 만든다.

## scenario.md 형식

1. 중심 질문 / 결과물 / 학습목표
2. 구간별 시간표: 시작~끝, 목표, 강사 행동, 학습자 행동
3. 장면별 강의안: 말할 내용, 던질 질문, 다음 장면으로 넘어가는 문장
4. 실습: 상황, 입력 자료, 실행 프롬프트 또는 활동 지시, 성공 기준, 대안
5. 자료·Q&A·후속 미션

시간표에는 설명, 실습, 회고, 질문, 전환 시간을 포함한다. 목표와 연결되지 않는 장면은 줄인다. 가상 사례는 실제 사례처럼 제시하지 않는다.

## deck.json 형식

필수 루트 필드:

| 필드 | 형식 | 의미 |
|---|---|---|
| title | 문자열 | 발표 제목 |
| topic | 문자열 | 교육주제 |
| audience | 문자열 | 교육 대상 |
| durationMinutes | 양수 | 전체 시간(분) |
| assumptions | 문자열 배열 | 명시한 가정. 없으면 빈 배열 |
| objectives | 문자열 배열 | 학습목표 1개 이상 |
| slides | 객체 배열 | 슬라이드. 모든 minutes 합계가 전체 시간과 일치 |

각 슬라이드:

| 필드 | 형식 | 의미 |
|---|---|---|
| id | 중복 없는 문자열 | 수정·추적용 식별자 |
| kind | 아래 값 | 교육상 역할 |
| layout | 아래 값 | 시각 구성 |
| title | 문자열 | 큰 제목, 짧은 한글 문장 권장 |
| message | 문자열 | 핵심 메시지 하나 |
| minutes | 0보다 큰 숫자 | 이 장의 설명·활동 포함 시간 |
| items | 문자열 배열, 선택 | 화면에 표시할 항목 |
| prompt | 문자열, 조건부 | exercise 또는 prompt 레이아웃에서 필수 |
| success | 문자열, 조건부 | demo/exercise의 성공 기준 |
| fallback | 문자열, 조건부 | demo/exercise의 막혔을 때 대안 |
| notes | 객체 | say, ask, transition 문자열 모두 필수 |
| sources | 객체 배열, 선택 | label과 http(s) url. 실제 확인한 자료만 |

kind: `opening`, `agenda`, `concept`, `demo`, `exercise`, `reflection`, `resources`, `qa`, `closing`.
opening/agenda/resources/qa/closing은 각 1장 이상 포함한다. 실습을 요청하지 않은 강연에서는 demo/exercise를 강제하지 않는다.

layout: `hero`(한 문장 강조), `cards`(최대 4항목), `split`(정확히 2항목 비교), `steps`(최대 5단계), `prompt`(복사할 실습 지시문). 목록이 더 길면 장을 나눈다.

노트의 say는 실제 강사가 할 말, ask는 참여 질문, transition은 다음 장으로 연결하는 말이다. 실습 시간이 길면 노트에 중간 안내 시점도 적는다.

모든 문자열은 일반 텍스트다. HTML 태그나 Markdown으로 스타일을 넣지 않는다. 줄바꿈은 프롬프트와 노트에 사용할 수 있다. 긴 내용은 노트로 이동하고, sources는 화면에서 열 수 있는 근거 링크다. 로컬 참고 파일명은 items 또는 notes에 적는다.

## 유지보수

`deck.json`이 슬라이드 내용·장수·시간의 기준이다. HTML은 생성물이다. 시나리오를 바꾸면 JSON도 갱신하고, JSON을 바꾸면 시간표·실습 설명과 HTML을 갱신한다. 다른 주제를 만들 때 예제 JSON의 주제·사례·가정을 그대로 남기지 않는다.
