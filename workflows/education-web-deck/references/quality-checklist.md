# 발표 전 검증

qa.md에는 항목별로 PASS/FAIL/NOT RUN과 증거를 남긴다. 체크박스를 채운 것만으로 검증했다고 말하지 않는다.

## 교육 내용

- 요청된 주제·대상·시간·실습 조건이 결과물에 반영됐다.
- 각 학습목표에 직접 해보거나 확인할 행동이 있다.
- 실습은 입력과 성공 기준이 구체적이고, 연결/로그인 실패 시 대안이 있다.
- 강의·전환·실습·Q&A를 합친 시간이 입력 시간과 같다.
- 아젠다, 회고, 자료, 질문 시간과 다음 행동을 찾을 수 있다.
- 가정·가상 사례·확인하지 못한 최신 정보가 구별된다.
- 링크의 내용이 해당 주장과 맞는다. 불필요한 통계·인용은 만들지 않았다.

## 파일과 실행

- render-deck.mjs의 --check가 통과한다.
- 생성된 파일 하나를 열면 CSS/JS/폰트를 다운로드하지 않고 표시된다.
- 주제·가정·시간·장수·발표자 노트가 다른 주제의 예제 값으로 남지 않았다.
- 기존 출력 덮어쓰기에는 명시적 --force가 필요하다.
- 변경한 코드에 대해 저장소의 필수 빌드를 실행한다.

## 실제 화면

- 모든 슬라이드를 1366×768, 1920×1080, 좁은 화면에서 확인한다.
- 큰 제목·한글·긴 링크·프롬프트가 잘리거나 화면 밖으로 나가지 않는다.
- 화살표/Space/Home/End, 전체보기 O, 노트 N, 도움말 ?, 전체화면 F가 동작한다.
- 링크·버튼·텍스트 입력·선택 중 단축키가 사용자 조작을 방해하지 않는다.
- 전체보기에서 키보드로 선택할 수 있고, 닫으면 포커스가 자연스럽게 돌아온다.
- 해시 직접 열기와 뒤로/앞으로 이동이 슬라이드에 반영된다.
- 프롬프트 복사가 되거나, 실패할 때 직접 복사할 수 있는 텍스트와 안내가 나온다.
- 네트워크를 차단해도 기본 발표 기능이 유지된다.
- 인쇄 미리보기에서 모든 장이 나오며, 노트·조작부가 발표면을 가리지 않는다.
- 노트는 청중에게도 보이는 동일 화면 기능이라고 안내한다.

화면 검사를 할 수 없으면 정확히 어떤 항목이 미실행인지 남긴다. Node 검증이나 앱 빌드로 브라우저 검사를 대체하지 않는다.
