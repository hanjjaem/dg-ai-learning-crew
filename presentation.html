AI 러닝크루 2기 특별 교육 세션

비개발자 공무원의 AI 실전 페어 프로그래밍 워크플로우

프롤로그 단톡방을 넘어선 독립 플랫폼으로
Case Study · Dong-gu AI Learning Crew 2nd

"코딩 몰라도 됩니다.
질문과 통제권 만 쥐고 계세요."

동구청 크루원들이 매일 쓸 웹서비스를 만드는 과정에서,
현업 기획자가 AI 에이전트에게 실제로 어떤 말(프롬프트)을 던지고 어떻게 바로잡았는지 생생한 6단계 실무 워크플로우를 공개합니다.

✂️
Rule 01. 과감한 제거
불필요한 것은 쳐낸다

군더더기 기능을 뺄수록 동료들이 매일 쓰는 명품 툴이 됩니다.

📸
Rule 02. 스크린샷 피드백
말보다 캡처 한 장 투척

전문 개발 용어 없이 화면 사진 하나로 버그의 멱살을 잡습니다.

🏛️
Rule 03. 현업 관점 되묻기
"관리자 입장에선 어때?"

출장 면제, 회비 장부, 공휴일 등 실무 엣지케이스를 선제 방어합니다.

아래로 스크롤하여 실전 사례 시작하기 ↓
STEP 01 · 본질에 집중하기

"드롭다운 기능은 왜 있어야 될까? 단일화해."

🗣️ 실제 지시 프롬프트: "드롭다운 기능은 왜 있어야 될까? 단일화해. 헤더를 꾸미지 말고 구조적으로 분리해라. 1px 라인만 쓰고 그림자는 빼."

AI에게 개발을 맡기면 자꾸 기능과 화려한 장식을 과하게 넣으려 합니다. 기획자가 "이거 우리 크루원들이 진짜 써? 빼!"라고 제어해야 오래 봐도 눈이 피로하지 않은 진정한 업무용 SaaS가 탄생합니다.

💡 실습 포인트: AI의 과잉 친절을 쳐내고 단순함을 지켜내는 것이 기획자의 첫 번째 역할입니다.
STEP 02 · 사내 기존 자산 활용

"공모전 폴더 참고해서 이미지 어떻게 올렸는지 확인해봐"

🗣️ 실제 지시 프롬프트: "프롬프트뿐만 아니라 생성한 그림, HTML도 전시했으면 좋겠는데 가능해? D:\work\동구_공모전\app 이 폴더 참고해서 이미지 어떻게 올렸는지 확인해볼래?"

맨땅에서 "이미지 전시 기능 만들어줘"라고 하면 AI는 엉뚱한 라이브러리를 끌고 옵니다. 사내에 이미 성공적으로 구축된 다른 폴더 경로를 레퍼런스로 딱 지정해주면, AI가 그 코드를 스스로 열람하여 스토리지 업로드 방식과 모달 UI를 10초 만에 완벽 복제합니다.

💡 실습 포인트: 이미 잘 만들어진 파일이나 사내 프로젝트 경로를 AI에게 레퍼런스로 제시하세요.
STEP 03 · 캡처 1장의 시각적 피드백

"이게 뭐야? 모달이 내부에 파묻혀 있잖아. 재진단해!"

🗣️ 실제 지시 프롬프트: "이게 뭐야 상세 모달로 열려야 하는거 아니야? (화면 캡처 첨부) 아니 모달이 내부에 파묻혀있잖아. 재점검 해봐 재진단!"

웹 개발에서 가장 골치 아픈 CSS 포지션 갇힘 버그(Containing Block Trap)로 모달 상단이 잘려나갔습니다. 기획자는 복잡한 CSS를 알 필요가 없습니다. 이상하게 나온 화면을 캡처해서 던지며 "파묻혔잖아!"라고 질타하자, AI가 스스로 React Portal을 적용해 화면 전체를 덮는 웅장한 모달로 치료했습니다.

💡 실습 포인트: 말로 길게 설명하지 마세요. 화면 캡처 한 장이 백 마디 개발 용어보다 정확합니다.
STEP 04 · 사용자 경험(UX) 통제권

"버튼 말고 행을 눌러도 튕기는데 이게 맞아? 특정 버튼을 눌러야지."

🗣️ 실제 지시 프롬프트: "지금 아카이브에서 마우스 클릭하면 외부 링크로 연결되는 부분이 뭐뭐있어? 버튼 말고 행 전체를 눌러도 이동하는데 이게 맞아? 특정 버튼을 눌러야 이동시켜야지."

내용을 보려고 행을 눌렀는데 갑자기 ChatGPT 사이트로 튕겨나가면 사용자는 당황합니다. "행 클릭 = 우리 서비스 내부 모달", "`[ ↗ ]` 버튼 클릭 = 외부 사이트 새 탭"으로 명확히 분리 지시하여 사용자에게 100% 심리적 안정감을 부여했습니다.

💡 실습 포인트: "사용자가 의도하지 않은 화면 이동"은 나쁜 UX입니다. 클릭 규칙을 분명히 지정하세요.
STEP 05 · 관리자(총무) 관점 역질문

"관리자 입장에서 부족한 부분 없어?"

🗣️ 실제 지시 프롬프트: "관리자 입장에서 부족한 부분 없어?"

이 마법 같은 질문 한마디가 AI를 단순 코더에서 '동구청 총무과 실무 운영자'로 변신시켰습니다. 운영 중에 반드시 터질 4대 엣지 케이스(출장·연차 면제, 회비 엑셀 없는 장부, 공휴일 벌금 제외, 개인정보 블라인드)를 DB 설계 단계에서 미리 완벽히 세팅했습니다.

💡 실습 포인트: "현업 운영자 입장에서 빠진 게 뭐야?"라고 AI에게 되물어보세요. 놀라운 해결책을 줍니다.
STEP 06 · 실데이터 전환 & 깃허브 자산화

"샘플 지우고 실제 8만원 입금자 8명 반영해. 그리고 깃허브에 올려."

🗣️ 실제 지시 프롬프트: "초기 회비 8만원으로 수정해. 김남희, 남수현 등 8명 입금완료 처리. 이현아 복지정책과로 수정. 지금까지 작업한 내역 깃허브에 올려줘."

가짜 더미 데이터를 싹 비우고, 실제 16명 크루원 명단과 8명 완납(640,000원, 50%) 현황을 주입하여 살아있는 운영 시스템으로 전환했습니다. 마지막으로 GitHub에 프로젝트 전체를 안전하게 백업하여 공공 디지털 자산으로 확정 지었습니다.

💡 실습 포인트: 기획 검증이 끝나면 샘플을 과감히 비우고, 실제 데이터로 즉시 라이브 테스트를 진행하세요.
