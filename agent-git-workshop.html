CHATGPT에 입력할 메타 프롬프트
다음 상황에서 Codex에게 전달할 작업 프롬프트를 만들어줘.

상황:
- 새로운 교육장 PC다.
- 기존 프로젝트는 GitHub에 있다.

목표:

결과 프롬프트에 상황, 목표, 자료, 작업 순서, 금지 사항, 완료 조건, 결과 보고 형식을 포함해줘.
교육생이 먼저 각자 프롬프트를 생성합니다. 5분 뒤 옆 사람과 바꾸어 읽고, 빠진 조건 하나를 찾아 추가하게 하세요.

EXECUTION PROMPT

CODEX · 최초 인수인계
새 PC에서 기존 프로젝트를 이어서 개발할 수 있게 준비해줘.

저장소: https://github.com/hanjjaem/dg-ai-learning-crew.git

1. Git, Node.js, npm 설치 상태와 버전을 확인해.
2. 현재 폴더가 비어 있는지 확인하고 저장소를 clone해.
3. 복제된 저장소의 AGENTS.md와 README.md를 먼저 읽어.
4. 현재 브랜치, origin 주소, 작업 파일 상태를 확인해.
5. npm ci로 의존성을 설치해.
6. .env.example을 확인하고 필요한 설정만 알려줘. 값은 임의로 만들지 마.
7. npm run build를 실행해.
8. 소스, 원격 저장소, commit은 변경하지 말고 준비 결과를 보고해.

오류나 충돌이 있으면 덮어쓰지 말고 원인과 필요한 사용자 조치를 알려줘.
실행 전 저장소 주소와 현재 작업 폴더를 함께 확인합니다. Codex가 권한 승인을 요청할 수 있다는 점도 알려주세요. 승인 문구를 읽고 범위를 확인한 뒤 허용합니다.

HUMAN CHECKPOINT

에이전트가 멈췄다면
실패가 아니라 승인 지점.

LOGIN

GitHub 로그인

브라우저나 자격 증명 창에서 본인이 로그인합니다.

SECRET

환경변수 제공

.env.local 값은 채팅이나 Git에 올리지 않고 안전하게 제공합니다.

APPROVE

변경 승인

Diff와 Build 결과를 확인한 뒤 Commit과 Push를 지시합니다.

이 슬라이드는 매우 중요합니다. “에이전트가 다 한다”가 “사용자가 보지 않아도 된다”는 뜻은 아닙니다. 인증과 비밀정보, 외부 반영은 사용자가 통제합니다.
WORKSHOP 3 · 15 MIN

큰 기능보다 먼저,
작은 변경을 완주합니다.

CODEX · 안전한 변경 실습
AGENTS.md를 먼저 확인하고, 교육 실습용으로 README.md에 다음 내용을 추가해줘.

- 제목: 교육장 새 PC에서 이어서 개발하기
- Clone은 최초 1회, Pull은 이후 갱신이라는 설명
- 작업 시작 전 git status 확인 안내

기존 내용을 삭제하지 말고 자연스럽게 추가해.
관련 없는 파일은 수정하지 마.
완료 후 git diff와 npm run build 결과를 보고해.
아직 commit과 push는 하지 마.

실제 수업에서는 수강생별 브랜치에서 문구·색상·작은 컴포넌트 중 하나를 선택해도 됩니다.

첫 변경은 실패 비용이 낮고 Diff가 눈에 보이는 것으로 선택합니다. README 변경은 빌드에 영향을 주지 않지만, 이 프로젝트 규칙상 변경 뒤 build를 수행하는 습관까지 같이 연습합니다.
THE FOUR GATES

“됐습니다”보다 강한 말.
“검증했습니다.”

1Status무슨 파일이 바뀌었는가
2Diff원하는 내용만 바뀌었는가
3Build컴파일과 타입 검사가 통과했는가
4Secret.env와 개인정보가 빠졌는가
네 개의 관문을 손가락으로 세게 하세요. 특히 git status와 git diff는 “AI가 한 일을 사람이 읽을 수 있게 만드는 창”이라고 설명합니다.
REVIEW → COMMIT → PUSH

확인했다면 이제
프로젝트 이력으로 남깁니다.

CODEX · 검토 후 반영
현재 변경 사항을 최종 검토해줘.

1. git status와 git diff를 확인해.
2. 비밀키, .env.local, 개인정보, 생성 파일이 포함되지 않았는지 검사해.
3. AGENTS.md에서 요구하는 검증을 실행해.
4. 문제가 없으면 이번 작업과 관련된 파일만 커밋해.
5. 변경 내용을 나타내는 명확한 한국어 커밋 메시지를 작성해.
6. 현재 실습 브랜치를 origin에 push해.
7. 브랜치 이름, 커밋 해시, push 결과를 보고해.

main에는 직접 push하지 마.
여러 명이 함께할 때는 반드시 실습 브랜치인지 먼저 확인합니다. Push는 외부 상태를 바꾸므로, 바로 앞 슬라이드의 네 관문을 통과한 뒤에만 시킵니다.
THE SECOND COMPUTER

다른 PC에서는 Clone이 아니라
안전한 Pull.

CODEX · 최신 상태로 갱신
이 프로젝트를 GitHub의 최신 상태와 비교하고 안전하게 갱신해줘.

1. 현재 브랜치와 로컬 변경 사항을 확인해.
2. origin의 최신 정보를 fetch해.
3. 로컬과 원격 브랜치의 ahead/behind를 확인해.
4. 로컬 변경이 없고 원격보다 뒤처진 경우에만 git pull --ff-only을 실행해.
5. 로컬 변경, 충돌, 분기 상태가 있으면 덮어쓰지 말고 보고해.
6. 갱신 후 의존성 변경 여부를 확인하고 필요한 경우에만 npm ci를 실행해.
7. npm run build로 최종 검증해.
교육 첫 장면으로 돌아옵니다. 어제 집에서 Push한 결과를 오늘 교육장 PC에서 Pull하는 순간, “이어가기”가 완성됩니다.
CLASSROOM RULE

한 저장소.
여러 사람.
브랜치는 따로.

모두가 main을 건드리지 않습니다. 수강생별 브랜치에서 실습하고, 검토 뒤 합칩니다.

origin/main
training/민지
training/남희
training/소희
실습 시작 전에 브랜치 이름 규칙을 칠판에 고정합니다. 예: training/이름. main 직접 Push 금지를 공통 AGENTS.md나 첫 프롬프트에도 넣습니다.
STOP, REPORT, DECIDE

에이전트가 멈춰야 할 때,
사람이 결정합니다.

DIRTY
로컬 변경 발견

덮어쓰지 않고 변경 파일과 선택지를 보고

DIVERGED
서로 다른 커밋

강제 Push 없이 브랜치 상태를 설명

AUTH
GitHub 인증 필요

사용자가 로그인하고 권한 범위를 확인

ENV
환경변수 없음

값을 추측하거나 Git에 기록하지 않고 요청

“모르는 상황에서 멈추는 것”도 좋은 에이전트 행동입니다. 교육생에게 각 카드 중 하나를 골라, 에이전트가 어떤 형식으로 보고해야 하는지 말해보게 합니다.
FINAL TAKEAWAY

명령어를 외우지 않아도 됩니다.
하지만 결과는 읽어야 합니다.

상황을 설명하고 → 작업을 맡기고 → Diff와 Build를 확인하고 → GitHub에 남기세요.
